# 验收设计与需求追踪

## 1. 验收原则

- 先验证数据与权限不变量，再验证页面流程；不能只以“按钮可点击”作为通过。
- 每个状态动作同时检查成功路径、非法角色、非法状态、旧版本和重复请求。
- 所有时间使用可控时钟或数据库构造，避免真实等待 12/24/48 小时。
- 本轮按要求未执行任何测试；下表是后续测试阶段的可追踪验收基线。

| ----- | ------------ | -------------------------------------------------------------------------------------------------------------- |
| F-001 | 一线上报页   | 只出现电话、客户类型、区县、客户联系方式、具体需求、客户态度、一句话说明、可选录音和固定勾选；没有其他业务问题 |
| F-002 | 上报人电话   | 从账号自动带出、只读，提交体不能覆盖                                                                           |
| F-003 | 组织客户提示 | 精确显示“组织客户包含企业客户、政府及公共事业客户、个体工商户等”                                               |
| F-004 | 固定授权提示 | 精确显示“请确认客户已同意用于本次需求咨询。请勿填写客户身份证、银行卡、家庭成员等无关信息。”；未勾选不能提交   |
| F-005 | 字段边界     | 联系方式 1–200；具体需求只能从固定 10 项中去重选择 1–2 项；一句话说明可空且最多 50；纯空格拒绝                 |
| F-006 | 区县         | 仅显示后台启用区县，人工可选；页面不请求定位权限、不加载地图 SDK、不提交坐标                                   |
| F-007 | 退回重报     | 仅原上报人可编辑；重新确认授权，生成新修订和新 24h 轮次，旧修订保留                                            |
| F-008 | 菜单值往返   | 含“、”的单项及任意两项组合在保存、详情、重报和导出后仍保持原菜单项边界，不按标点误拆                           |

## 4. 流程与 SLA

| ID    | 场景             | 验收结果                                                                         |
| ----- | ---------------- | -------------------------------------------------------------------------------- |
| W-001 | 个人客户初审通过 | 仅列出本区县有效个人侧候选；经理必须选择一人，事务内复核后分派                   |
| W-002 | 组织客户初审通过 | 仅列出本区县有效组织侧候选；经理必须选择一人，事务内复核后分派                   |
| W-003 | 缺少承接覆盖     | 区县缺少有效经理或对应分侧承接人时，上报/重报被明确拒绝且不产生半成品数据        |
| W-004 | 初审退回         | 回到上报人；原因可见；当前 24h 轮次结束                                          |
| W-005 | 改派             | 仅本区县经理可改到同区县同分侧；原因必填；旧承接人立即失去正文访问               |
| W-006 | 暂缓             | 未来时间必填，不进入终审；到期由同一承接关系自动恢复，可提前恢复和多次暂缓       |
| W-007 | 暂缓陈旧任务     | 提前恢复或版本变化后，旧到期任务执行无副作用                                     |
| W-008 | 失败             | 原因必填，进入终审；通过后为 `CLOSED_FAILURE`                                    |
| W-009 | 初审计时         | 提交后 12h 半程提醒、24h 标记超时；超时不阻止审批                                |
| W-010 | 终审计时         | 结果提交后 24h 半程提醒、48h 标记超时；超时不阻止审批                            |
| W-011 | 新轮次           | 每次退回后的重报重置相应计时，旧轮次仍可审计                                     |
| W-012 | 上报人同步       | 分派、改派、暂缓、恢复、结果提交、退回、终审和超时均形成站内通知/时间线关键节点  |
| W-013 | 多经理待办       | 上报、重报、终审待办及 SLA 提醒/超时通知发送给本区县所有有效经理，不依赖默认经理 |
| W-014 | 关键人留痕       | 初审分派和改派事件保存承接人姓名/角色；后续停用账号不覆盖既有时间线              |

## 5. 并发、幂等和一致性

| ID    | 场景                 | 验收结果                                                |
| ----- | -------------------- | ------------------------------------------------------- |
| C-001 | 相同键相同请求重放   | 返回第一次的状态和版本，不重复事件/通知/分派            |
| C-002 | 相同键不同请求       | `409 IDEMPOTENCY_KEY_REUSED`                            |
| C-003 | 两个经理以同版本审批 | 只允许一个提交；另一个得到 `409 VERSION_CONFLICT`       |
| C-004 | 非法状态动作         | `422 INVALID_TRANSITION`，数据无部分更新                |
| C-005 | Outbox 重复投递      | 延迟任务 singleton＋业务状态复查，不重复提醒/恢复       |
| C-006 | 事务故障             | 任一业务写失败时，状态、事件、SLA、通知、幂等记录均回滚 |

## 6. 授权与隐私

| ID    | 场景             | 验收结果                                                                       |
| ----- | ---------------- | ------------------------------------------------------------------------------ |
| A-001 | 角色切换         | 服务端只按 `X-Role-Grant-Id` 当前授权判断，不叠加其他授权                      |
| A-002 | 系统管理员       | 可管理全部账号、角色、区县及人员同步，但商机列表、详情、录音均返回 403         |
| A-003 | 跨区县经理       | 商机详情和动作均返回 403                                                       |
| A-004 | 非当前承接人     | 即使曾承接过，也不能读取正文或提交结果                                         |
| A-005 | 市公司非成功正文 | 返回 403；成功正文只读，不能编辑、删除或重开                                   |
| A-006 | 音频             | 仅上报人、本区县经理、当前承接人、市公司成功库可播；访问有审计；无公开静态 URL |
| A-007 | 导出再验证       | 密码错误拒绝；令牌 5 分钟到期且只能用一次                                      |
| A-008 | Excel 公式注入   | 以 `= + - @` 开头的任意导出文本作为纯文本打开，不执行公式                      |
| A-009 | 明文泄露         | API/worker 日志、Outbox、数据库正文列和音频卷中找不到样例明文                  |
| A-010 | 音频到期         | 办结后默认 90 天删除密文文件，保留删除时间和 SHA-256 元数据                    |
| A-011 | 主数据留存       | 默认办结 3 年后只进入候选队列；未人工输入商机编号确认前不删除或匿名化          |

## 7. 账号、角色、人员与区县配置

| ID    | 场景             | 验收结果                                                                                                                                  |
| ----- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| R-001 | 账号搜索         | 姓名支持包含搜索；完整 11 位手机号可精确搜索；分页、状态、角色和区县筛选可组合且不突破权限域                                              |
| R-002 | 区县经理视图     | 只出现本区县具有一线/个人侧/组织侧授权的账号；其他区县、同级经理、市公司及更高角色均不可见                                                |
| R-003 | 区县经理配置     | 只能创建或调整本区县一线/个人侧/组织侧授权；不能启停整个账号、重置密码、配置同级或上级角色                                                |
| R-004 | 高级市公司管理员 | 可管理全区域业务角色和市公司角色；不能搜索、查看、创建、停用高级市公司管理员或系统管理员                                                  |
| R-005 | 系统管理员       | 可查看与管理全部配置角色；最后一个有效系统管理员授权无法撤销                                                                              |
| R-006 | 原子建号         | `POST /admin/users` 必须同时提交至少一个合法授权；任一授权失败时账号与全部授权共同回滚                                                    |
| R-007 | 单一配置源       | “区县承接覆盖”只汇总有效授权，不存在可编辑的第二套路由；授权新增/停用后覆盖数量与候选池同步变化                                           |
| R-008 | 停用保护         | 有未办结分派的承接人须先改派；有未办结商机时不能撤销该区县最后一名有效经理                                                                |
| R-009 | 区县顺序         | 业务下拉和管理表按原21个区县顺序显示，并在末尾追加天府新区、龙泉驿，共23个当前业务区县                                                    |
| R-010 | 密码边界         | 登录、创建、重置、改密和导出复核均只校验 6–12 位；不额外要求大小写、数字或特殊字符组合                                                    |
| P-001 | 完整人员表预检   | 含“人员编码、人员姓名”的文件被识别为 `FULL_DIRECTORY`；预检返回新增/更新/停用/跳过计数且不写库                                            |
| P-002 | 联系人简表预检   | 含“姓名、联系电话”的文件被识别为 `CONTACT_ONLY`；无效或重复联系方式按行告警并跳过                                                         |
| P-003 | 隐私列           | 身份证、银行卡、家庭联系方式、附件和未批准字段不落库；手机号以密文和盲索引保存                                                            |
| P-004 | 管理账号开通     | 仅系统管理员显式启用该选项并通过预检后，联系人简表前 6 个有效联系人和指定且存在于表内的手机号均获得系统管理员授权；重复命中只保留一条授权 |
| P-005 | 初始密码         | 所有新账号及管理员重置密码均为手机号后 6 位并强制首次修改；重跑同步不重置既有账号密码                                                     |
| P-006 | 快照隔离         | `SNAPSHOT` 只停用同来源类型中缺失的人员；简表命中完整人员时不清空组织/职务资料；关联账号明确标记待复核且不自动撤权                        |
| P-007 | 职务模板         | 一个职务可建议多个角色；建议只预选人工开通表单，保存或修改模板不会自动改变任何账号授权                                                    |
| P-008 | 大表同步         | 9,000 级样例可按批预取和每 500 行批量 upsert；编码与手机号命中不同人员时整批拒绝而非静默合并                                              |
| P-009 | 批量开户预检     | 系统管理员按现有关键词搜索跨页预检；已有账号、停用人员、无手机号、未映射和歧义项均只记录跳过原因，不创建账号                              |
| P-010 | 批量开户执行     | 合格人员由 worker 分批创建账号，每人仅获得 `FIELD_REPORTER` 与目标区县；重复执行幂等，单项失败不回滚其他成功项                            |
| P-011 | 区县映射规则     | 联系人简表固定归金牛；龙泉驿优先于天府新区；规则可由系统管理员维护，规则变更后旧预检不可执行                                              |
| P-012 | 批量结果导出     | 系统管理员重新认证后可导出批次明细；只含掩码手机号、区县、状态和原因，不含明文密码或完整手机号                                            |

## 9. 兼容性与非功能

| ID    | 场景         | 目标                                                                                            |
| ----- | ------------ | ----------------------------------------------------------------------------------------------- |
| N-001 | 50 并发基线  | 4 vCPU/8 GB 环境下列表/详情 p95 ≤ 1.5s，状态迁移 p95 ≤ 2s，错误率 <1%                           |
| N-002 | 10 万商机    | 角色范围列表与成功库分页不做全表明文扫描                                                        |
| N-003 | 5 万行导出   | 在 120s 内完成且 API 内存不随总行数线性增长                                                     |
| N-004 | 响应式       | Android 微信/Chrome、iOS 微信/Safari、桌面 Edge/Chrome 核心流程不横向溢出；表格允许受控横向滚动 |
| N-005 | 麦克风限制   | localhost 可验收；局域网手机 IP 非安全上下文时明确提示，正式真机验收使用受信任 HTTPS            |
| N-006 | Compose 重启 | API/worker 重启后未处理 Outbox、SLA 和暂缓任务可继续，无状态丢失                                |
| N-007 | 备份恢复     | 在隔离环境恢复 PostgreSQL 与音频卷后，抽样正文可解密、音频可播放、迁移版本一致                  |

## 10. 明确不验收的当前范围

- 浏览器/微信定位、地图选点、经纬度、逆地理编码和自动区县判断。
- 语音识别、语音转文字、转写校对和任何 ASR 厂商接口。
- 短信、邮件、企业微信等外部通知。
- 正式生产部署、等保结论或法律合规认证。
